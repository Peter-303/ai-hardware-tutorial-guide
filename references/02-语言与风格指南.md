# ✍️ 语言与风格指南

> 教程不是技术文档，是**一个懂行的朋友在手把手带你**。
> 本指南的所有规则都来自 Datawhale 头部教程的真实写法，每条都配正反例。

---

## 🧭 一条总原则

**每写一句话，问自己：学习者看到这里，是想继续，还是想关掉？**

技术教程的最大敌人不是"难"，是"孤独感和挫败感"。我们的文字要持续传递三个信号：

1. **"你并不孤单"**——有人陪、有群问、卡住很正常
2. **"你能做到"**——门槛说在前面，承诺具体可实现
3. **"这很值得"**——每章都能看到自己的进度和成果

---

## 一、称呼与语气

| 规则 | ✅ 这样写 | ❌ 别这样写 |
|---|---|---|
| 称呼学习者 | "你""大家""小伙伴" | "用户""读者朋友们"（太正式） |
| 自称 | "我们""本教程" | "笔者""鄙人" |
| 语气 | 亲切、鼓励，可以用"~"和"！" | 命令式、考核式 |

**真实样本**：
> "本次课程将带领大家从零开始，手搓一台属于自己的 AI 机器人。" —— whale-bot
>
> "欢迎大家一起加入进来啊~！" —— tiny-universe

**对比**：
- ✅ "接线完成后，你的小车就拥有'耳朵'啦！接下来我们让它开口说话~"
- ❌ "完成上述接线操作后，进入下一章节。"

## 二、标题公式

### 章节标题：**说成果，不说知识点**

> 公式：**动词 + 你的 + 成果**（可搭配 emoji）

| ❌ 知识点式（劝退） | ✅ 成果式（想看） |
|---|---|
| 第三章 语音识别原理 | 第三章 让小车听懂你的话 🎤 |
| 第五章 PWM 电机调速 | 第五章 给小车装上"油门" 🏎️ |
| 附录 常见报错 | 附录 卡住了？先来这看看 🛟 |

### README 分区标题：emoji + 短词

Datawhale 新项目的高频分区词，直接可用：

`🎯 你将收获什么` `🗺️ 学习路径` `🛍️ 新手无忧套件` `🛠️ 硬件清单` `💻 快速上手` `🤝 参与贡献` `✨ 项目亮点` `📢 News 更新`

> 📌 emoji 密度参考：新仓库（so-large-lm、hello-agents）密度高，老仓库偏朴素。我们是新项目，**分区标题用 emoji，章节内标题克制用**。

## 三、章节开头"三段式"

每章开头固定写三小段（各 1-2 句话）：

```markdown
这一章我们要做什么 → 为什么值得做 → 做完你能得到什么
```

**示例**：

> 上一章里，小车已经能跑起来了。这一章，我们要给它装上"嘴巴"——让它能开口回答你的问题。
> 语音对话是这台小车最"哇塞"的功能，也是你发朋友圈的重头戏。
> 完成本章后，对着小车问"今天天气怎么样"，它会用大模型的答案回应你。

> ⚠️ 避免一上来就抛概念："本章介绍 TTS 文本转语音技术及其在嵌入式端的实现方案。" ——读者还没上车，你就开始念说明书了。

## 四、降低焦虑的表达（最重要的风格资产）

### 4.1 门槛写在明处

在项目受众部分明确写"你需要什么 / 不需要什么"：

> ✅ "你只需要：一颗好奇心 + 一台能上网的电脑。**不需要**会焊电路，**不需要**学过单片机，**不需要**买任何书。"
>
> （真实样本：llm-universe 写明"对人工智能基础、算法基础没有任何要求，仅需 Python"；whale-bot 写明"零门槛上手"）

### 4.2 替代"很简单"的一百种说法

| ❌ 劝退词 | 为什么有害 | ✅ 换成 |
|---|---|---|
| "显然""很明显" | 读者觉得不显然时，只会怀疑自己 | "这里的关键是……" |
| "很简单""一看就懂" | 做不好的人瞬间泄气 | "跟着下面三步走就行" |
| "众所周知" | 新人恰恰不知道 | "很多小伙伴第一次会好奇：……" |
| "只需要……就行了"（对复杂操作） | 轻描淡写放大挫败感 | "这一步稍多，慢慢跟着图来，大约需要 10 分钟" |

### 4.3 卡住时的"接住"话术

教程里每个高危步骤（烧录、焊接、配网）后面跟一句"接住"的话：

> ✅ "如果烧录报错 `xxx`，别慌，90% 的小伙伴都是驱动没装，点这里看解决办法 →"
> ✅ "这一步翻车率最高，我们录了 30 秒小视频，跟着做就好~"
> ✅ "实在搞不定？带着报错截图来群里问，助教每天都在。"

## 五、硬件教程特有写法

### 5.1 步骤写法：**操作 + 图 + 预期结果** 三件套

每个操作步骤必须包含：

```markdown
1. 把红色导线插到主控板的 5V 引脚（见图 3-2）
   📷 [清晰的实拍图，关键位置画圈标注]
   ✅ 插好的样子：红线从板子右侧伸出，金属端子完全没入
```

> 硬件教程的读者**看不到实物就不会操作**。whale-bot 连"烧录前的选项勾选"都放了完整截图——这就是标杆。

### 5.2 版本号写到牙齿

- ✅ "Arduino IDE 2.1.4 及以上""ArduinoJson 库 **7.4.1**"
- ❌ "安装最新版即可"（三个月后"最新版"就是新的坑）

### 5.3 安全提示：严肃但不吓人

> ⚠️ **安全提示**：锂电池充电时请有人在场，首次充电建议在白天进行。这一步不吓人，但值得认真对待——我们的小车要陪大家很久，安全第一。

（用单独引用块 + ⚠️，不用大段红字恐吓）

### 5.4 购买指引：替新手把坑趟完

每个元件给出：**精确型号 + 常见买错的坑 + 参考价位**

> ✅ "N20 减速电机（12V 300RPM 版）。注意别买成 6V 版——长得一模一样！认准商品页的电压参数。单只约 8-12 元。"

## 六、情感化收尾

重要节点（章节末、教程末、README 末）用一句有温度的话收尾，形成项目的"语言签名"：

> - "点亮小车的那一刻，记得拍照打卡——这是你亲手造出来的智能生命。🐳"
> - "星火点点，汇聚成海。我们在下一期组队学习等你。"

> 📌 Datawhale 的语言签名是 "for the learner，和学习者一起成长"。建议我们也固定一句自己的 slogan，在所有物料中复用。

## 七、术语与格式细节

| 项目 | 规范 |
|---|---|
| 中英混排 | 中英文之间加空格："使用 ESP32-S3 主控" |
| 技术术语 | 首次出现给中文解释 + 英文原词："麦克纳姆轮（Mecanum Wheel，一种可以横着走的轮子）" |
| 报错信息 | 用代码块原样展示，方便搜索 |
| 关键参数 | 加粗：**300RPM**、**5V** |
| 段落 | 每段不超过 4 行，多用小标题切碎 |
| 图片 | 实拍图 > 示意图；关键位置画圈/箭头标注 |

## 📋 发布前风格自检清单

- [ ] 全文没有"显然/很简单/众所周知/只需要"
- [ ] 每章开头有"三段式"，每章标题是成果式
- [ ] 门槛和前置要求在显眼位置写清了
- [ ] 每个高危步骤都有"卡住了怎么办"
- [ ] 每个操作步骤都有图 + 预期结果
- [ ] 所有软件/库标注了版本号
- [ ] 每个元件有防买错提示
- [ ] 安全提示齐全且语气得当
- [ ] 章末和教程末尾有情感化收尾
